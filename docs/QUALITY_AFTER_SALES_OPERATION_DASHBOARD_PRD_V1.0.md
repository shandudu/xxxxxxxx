# 质量与售后运营驾驶舱 PRD V1.0

## 1. 目标

为质量经理、客服负责人和工厂主管提供 NCR、CAPA/8D、客户投诉、RMA 与售后执行单的统一运营视图，围绕“发现—责任—SLA—升级—关闭—复盘”形成可追溯闭环。

## 2. 核心指标

- 各对象按状态的总量、开放量、已关闭量和超期量。
- 平均关闭时长：从创建时间到关闭/完成时间，按对象分别统计。
- SLA：规则目标时长、预警提前时长、截止时间、责任人、告警状态。
- 重复问题：按 NCR 缺陷描述归一化聚合，展示重复次数和 Top 问题。
- 库存影响：RMA/售后相关库存事务数量、数量变动合计和绝对影响量。
- 责任人待办和升级：告警责任人、确认时间、升级级别、升级时间。

## 3. SLA 规则

默认规则为 NCR 72/48 小时、CAPA 168/120 小时、投诉 120/72 小时、RMA 96/72 小时、售后执行单 72/48 小时（目标/预警）。规则可按对象、严重度启停和调整。工作项首次进入系统时落截止时间，定时刷新告警为 OPEN、WARNING、OVERDUE；关闭对象对应告警自动 CLOSED。

## 4. 接口与页面

- `GET /api/v1/mes/quality/operation-dashboard`：返回状态分布、超期、平均关闭时长、重复问题、库存影响和待办汇总。
- `GET /api/v1/mes/quality/sla-alerts`：按状态/责任人筛选告警。
- `POST /api/v1/mes/quality/sla-alerts/{id}/acknowledge|escalate|close`：确认、升级、关闭告警。
- 质量页面增加“运营驾驶舱”页签：指标卡、重复问题榜、库存影响、告警待办表；点击告警可下钻到 NCR/CAPA/RMA/售后明细页签。

## 5. 权限与验收

看板和告警查询沿用 `mes:quality:view`；告警状态变更使用 `mes:quality:mrb:execute`。验收要求：MySQL 迁移可升级/回滚、索引存在、接口返回稳定、告警状态可闭环、全量后端测试通过、前端 typecheck/build 通过。
