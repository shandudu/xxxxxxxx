# 批次效期、FEFO、质量隔离与召回闭环 PRD V1.0

## 1. 目标

在现有批次、库存、质量检验、销售发货和正反向追溯基础上，形成：

> 效期策略 → 临期预警 → 过期自动冻结 → FEFO 自动分配 → 质量复检 → 延期放行/报废 → 批次召回 → 客户与库存处置闭环

数据库继续使用 MySQL，所有冻结、库存扣减、召回影响和状态变化必须可审计、可幂等、可回滚。

## 2. 业务范围

### 2.1 效期策略

- 每个物料最多一条有效策略；配置预警天数、严重预警天数、出库最小剩余效期、是否启用 FEFO、过期自动冻结和是否必须复检。
- 严重预警天数不得大于普通预警天数。
- 有效期来自批次 `expiry_date`；采购/生产创建批次时继续复用物料保质期自动计算能力。

### 2.2 临期预警与过期冻结

- `剩余天数 <= 预警天数` 产生 `WARNING`；`<= 严重天数` 产生 `CRITICAL`；`<= 0` 产生 `EXPIRED`。
- 同一批次只保留一条当前效期预警，重复同步只更新，不重复生成。
- 有正库存的过期批次自动设置为 `LotStatus.HOLD + QualityStatus.HOLD`，并创建一条 `EXPIRED` 质量隔离单。
- 已延期放行、无库存或风险解除后关闭预警。

### 2.3 FEFO 出库

- 销售发货支持 `auto_fefo=true`，按有效期升序、生产日期升序、批次号升序分配库存。
- 自动分配可以跨同一仓库的多个库位和多个批次，生成多条实际发货行。
- 候选批次必须：有效、质量放行、无未关闭隔离、未过期且满足最小剩余效期。
- 库存不足时整张发货事务回滚，不产生半张发货单。
- 手工指定批次仍保留，但库存出库服务统一阻止过期、冻结或未放行批次，不能绕过 FEFO 规则。

### 2.4 质量隔离、复检、延期放行与报废

- 过期隔离单可以创建一张幂等 `RETEST` 检验单。
- 检验 PASS 后，必须填写新的有效期且新有效期晚于当前时间，才能释放批次。
- 检验未通过不得释放；批次保持冻结，可进入现有 NCR/MRB 流程。
- 报废按批次所有正库存库位逐行生成 `SCRAP` 库存流水；重复报废不重复扣减。

### 2.5 批次召回

- 从问题根批次发起召回，沿现有批次谱系向下游展开。
- 自动识别受影响的在库批次、销售发货行和客户。
- 在库批次自动隔离；已发货记录形成客户通知/退回待办。
- 召回项支持 `PENDING/QUARANTINED/NOTIFIED/RETURNED/CLOSED` 状态。
- 所有召回项完成后方可关闭召回；关闭召回不会释放仍处于过期或其他隔离中的批次。

## 3. 核心状态

- 效期预警：`OPEN → ACKNOWLEDGED → CLOSED`
- 质量隔离：`OPEN → AWAITING_RETEST → RELEASED/SCRAPPED`
- 召回：`ACTIVE → CLOSED/CANCELLED`
- 召回项：`PENDING/QUARANTINED → NOTIFIED/RETURNED/CLOSED`

## 4. 数据实体

- `mes_shelf_life_policy`
- `mes_lot_expiry_alert`
- `mes_lot_quality_hold`
- `mes_lot_recall`
- `mes_lot_recall_item`

## 5. API

- 效期策略查询与按物料保存。
- 效期预警同步、查询和确认。
- FEFO 候选与自动分配。
- 隔离单查询、创建复检、延期放行和报废。
- 召回创建、查询、召回项处理和关闭。

## 6. 权限

- `mes:inventory:shelf-life:view`
- `mes:inventory:shelf-life:config`
- `mes:inventory:shelf-life:execute`
- `mes:inventory:recall`

## 7. 验收标准

1. 临期等级计算正确，重复同步幂等。
2. 过期批次自动冻结，手工出库和生产领料均被库存服务拒绝。
3. FEFO 可跨批次、跨库位分配，最早有效期先出，库存不足整单回滚。
4. 过期隔离复检 PASS 且延期后才能放行；报废库存流水幂等。
5. 召回可识别下游批次、库存、销售发货和客户，并冻结剩余库存。
6. Alembic 在 MySQL 上升级、降级、重新升级通过。
7. 后端测试、MySQL 回滚验收、前端类型检查和生产构建通过。
