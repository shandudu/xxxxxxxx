# MES + ERP 制造闭环演示模块 PRD V1.0

## 1. 业务目标

为已实现的供应商、物料、库存、BOM、工艺路线、工单、生产、质量、销售和追溯模块提供一条可重复验证的最小制造闭环。演示模块不替代任何业务模块，也不新增业务事实的平行写入逻辑；它只调用已有服务和 API 创建一套带统一演示标识的数据，并可返回闭环验收结果。

目标闭环：

```text
供应商 → 原材料/批次入库 → BOM/工艺路线 → 工单 → 领料 → 工序报工
→ 成品批次入库 → 质量放行 → 客户销售订单 → 发货 → 正反向追溯
```

## 2. 使用场景

- 新环境安装后快速获得可演示的 MES + ERP 样例数据。
- 开发或验收时通过一键校验确认跨模块关系仍正确。
- 培训时使用稳定的业务编号定位单据与追溯链路。

## 3. 依赖与边界

依赖 `material`、`warehouse`、`supplier`、`customer`、`inventory`、`bom`、`routing`、`production`、`quality`、`sales` 和 `trace`。

- 主数据和业务单据仍由原模块表保存。
- 库存变化必须通过 `InventoryService.post_transaction` 或既有业务服务完成。
- 工单必须保存 BOM、Routing 及工序快照，不动态读取最新版本。
- 追溯关系统一为上游到下游，不创建反向重复关系。
- 不允许以 `SELECT MAX(id) + 1` 生成编号；演示编号使用固定业务代码并有幂等检查。
- 一期只创建和校验数据，不提供一键物理删除。需要清理演示数据时由管理员按明确单据逐项处理，避免破坏真实业务数据。

## 4. 演示对象

| 对象 | 固定业务代码 |
| --- | --- |
| 供应商 | `DEMO-SUP-001` |
| 客户 | `DEMO-CUS-001` |
| 原材料 | `DEMO-RM-001` |
| 成品 | `DEMO-FG-001` |
| 仓库/库位 | `DEMO-WH-001` / `DEMO-LOC-001` |
| BOM | `DEMO-BOM-FG-001` V1 |
| 工艺路线 | `DEMO-RT-FG-001` V1 |
| 工单 | `DEMO-WO-001` |
| 成品批次 | `DEMO-FG-LOT-001` |
| 销售订单 | `DEMO-SO-001` |

实际编号是否增加后缀由现有单号规则决定；所有对象都通过 `demo_key`/备注中统一标识关联，不把名称作为外键。

## 5. 生命周期与业务规则

1. 若演示主数据已经存在，创建动作必须复用已存在且有效的对象，不创建重复记录。
2. 若演示工单已完成、成品已质量放行并已发货，则创建动作直接返回已完成状态，确保幂等。
3. 每个跨模块步骤在独立明确事务中执行；失败时当前步骤回滚，返回失败步骤和业务错误码。
4. 验收接口只读，检查核心对象、库存流水、工单快照、质量放行、发货及正反向追溯是否同时存在。
5. Demo 不伪造设备实时数据、APS 排程或成本数据；这些由各自模块后续演示场景覆盖。

## 6. 数据模型

### 6.1 演示运行记录

新增 `mes_demo_run`，仅记录演示编排结果，不保存业务明细 JSON：

| 字段 | 说明 |
| --- | --- |
| `run_no` | 演示运行编号，唯一 |
| `scenario_code` | 固定为 `MANUFACTURING_HAPPY_PATH` |
| `status` | `RUNNING`、`COMPLETED`、`FAILED` |
| `started_at` / `completed_at` | 运行时间 |
| `failed_step` | 失败步骤代码，可空 |
| `error_message` | 业务错误摘要，可空 |

业务单据关系通过已有表的稳定 ID、编号和快照维护；运行记录不复制业务关系模型。

## 7. API 与权限

| 方法 | 地址 | 权限 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/mes/demo/manufacturing-happy-path/run` | `mes:demo:run` | 创建或续跑演示闭环 |
| GET | `/api/v1/mes/demo/manufacturing-happy-path/status` | `mes:demo:view` | 获取步骤状态与对象定位信息 |
| POST | `/api/v1/mes/demo/manufacturing-happy-path/verify` | `mes:demo:view` | 只读校验闭环一致性 |

## 8. 页面

菜单“制造演示中心”位于 MES 制造管理下：

- 展示 10 个闭环步骤及当前状态。
- 显示关键业务编号，可跳转到原业务页面。
- 管理员可执行“创建/续跑演示数据”和“重新校验”。
- 页面必须清晰提示：不会自动删除任何业务数据。

## 9. 错误码

- `DEMO_SCENARIO_RUN_IN_PROGRESS`
- `DEMO_REQUIRED_MASTER_DATA_INVALID`
- `DEMO_HAPPY_PATH_STEP_FAILED`
- `DEMO_HAPPY_PATH_INCOMPLETE`
- `DEMO_HAPPY_PATH_INCONSISTENT`

## 10. 一期明确不做

- 不生成或删除任意真实业务数据以外的“假库存余额”。
- 不绕过库存、质量、生产和销售服务直接写核心业务表。
- 不自动处理已有演示数据与用户手工修改之间的冲突。
- 不覆盖 APS、设备运维、OEE 的独立验收场景。
- 不提供批量清理/物理删除入口。

## 11. Definition of Done

1. 运行记录迁移、模型、服务、API、菜单和前端页面均完成。
2. 创建接口可重复调用且不会重复创建完成态对象。
3. 失败步骤有明确错误码，当前步骤事务回滚。
4. 校验接口覆盖库存流水、工单快照、质量、发货、追溯关键节点。
5. 后端服务/API 测试、前端类型检查和生产构建通过。
6. 用真实数据库事务执行一次演示并验证结果后回滚，数据库无测试残留。
