# 供应商质量管理（SQM）PRD V1.0

## 1. 目标

将现有采购收货、IQC、NCR/MRB、供应商和采购 OTIF 串成可执行闭环：

`采购收货 → IQC → 不合格/NCR → SCAR 供应商整改 → 复验 → 供应商评分 → 采购策略联动`

## 2. 核心规则

1. 来料检验出现 FAIL/PARTIAL 后创建 NCR，系统自动建立一张草稿 SCAR，并追溯收货单、供应商、物料、批次和不合格数量。
2. SCAR 发布后记录整改期限；供应商整改内容至少包含遏制措施、根因、纠正措施和预防措施。
3. 整改回复后由质量人员发起复验。复验通过才能关闭 SCAR；复验失败则驳回整改并保留采购风险。
4. 供应商评分按滚动周期计算：IQC 批次通过率、数量合格率、SCAR 有效率/按期率、采购 OTIF。
5. 评分生成不可变快照，得到 A/B/C/D 等级与 APPROVED/CONDITIONAL/SUSPENDED/PENDING 采购决策。
6. D 级或存在未关闭的严重 SCAR 时，采购下单必须在服务层硬拦截；C 级供应商继续采购但强制其供料关系执行 IQC。
7. 自动联动更新供应商质量状态；所有判断以数据库事务内状态为准，不依赖前端按钮。

## 3. 状态机

- SCAR：DRAFT → ISSUED → RESPONDED → RETEST_PENDING → CLOSED/REJECTED。
- 评分等级：A（优秀）、B（合格）、C（条件准入）、D（暂停采购）、UNRATED（样本不足）。
- 采购决策：APPROVED、CONDITIONAL、SUSPENDED、PENDING。

## 4. 默认评分公式

- IQC 得分 = 批次通过率 × 60% + 数量合格率 × 40%。
- 整改得分 = SCAR 有效率 × 70% + 按期关闭率 × 30%；无 SCAR 时按 100 分。
- 质量得分 = IQC 得分 × 80% + 整改得分 × 20%。
- 综合得分 = 质量得分 × 70% + OTIF 得分 × 30%。
- 默认阈值：A ≥ 95、B ≥ 85、C ≥ 70、D < 70；阈值和权重允许按供应商配置。

## 5. 页面

- SQM 驾驶舱：待整改、逾期、复验中、暂停采购、等级分布。
- SCAR 列表：发布、录入整改回复、发起复验、验证关闭。
- 评分与策略：配置周期/阈值/权重、重新评分、查看评分历史与采购决策。

## 6. 权限

- `mes:quality:sqm:view`：查看 SQM。
- `mes:quality:sqm:scar`：发布和维护 SCAR。
- `mes:quality:sqm:verify`：复验与关闭。
- `mes:quality:sqm:policy`：评分策略与采购联动。

## 7. 验收标准

- IQC 不合格 NCR 能自动生成且只能生成一张 SCAR。
- 未回复 SCAR 不能发起复验，复验未通过不能关闭。
- 评分可重复运行并生成历史快照。
- D 级或严重未关闭 SCAR 的供应商无法新建采购订单。
- MySQL migration 可升级、降级；验证脚本全部在事务中执行并回滚业务数据。
