# MRP 净需求 → 采购/生产建议 → ATP/CTP 自动重算 PRD V1.0

## 1. 背景与目标

当前系统已经具备 MPS 需求导入、BOM 多层展开、库存/采购在途/生产在制净额计算，以及计划订单固定、下达能力。本版本将其串成可执行闭环：

> 销售订单/MPS 需求 → MRP 净需求 → 采购或生产建议 → 正式业务单据 → ATP/CTP 自动重算 → 交期风险更新

目标是让计划员看到缺口后可以直接执行建议，并在建议转为采购订单或生产工单后立即刷新销售订单承诺状态。

## 2. 业务规则

### 2.1 净需求

- 毛需求按 MPS 需求日期和 BOM 层级展开。
- 供给扣减顺序：可用库存 → 已创建的采购订单草稿/已确认/部分收货采购在途 → 已创建的生产工单草稿/已下达且未完工生产工单；由 MRP 释放产生的草稿单据作为 CTP 候选供给。
- `net_requirement = max(gross_requirement - inventory - purchase - production, 0)`。
- 可采购物料生成 `PURCHASE` 计划订单；有有效 BOM 的自制物料生成 `PRODUCTION` 计划订单；两者都不满足时记录 `uncovered_quantity`。
- 计划订单的建议下达日 = 需求日期 - 对应提前期，不能因为建议执行而修改原始 MPS 需求。

### 2.2 建议订单生命周期

`PLANNED → FIRM → RELEASED`。

- `PLANNED`：MRP 计算产生，允许计划员调整或重新计算。
- `FIRM`：计划员确认建议，不再被普通重算覆盖。
- `RELEASED`：采购建议转采购订单草稿，生产建议转生产工单草稿；保存正式单据编号和来源关系。
- 释放要求：采购必须选择供应商；生产必须存在有效 BOM 和工艺路线。

### 2.3 ATP/CTP 自动重算

以下事件触发所有未关闭销售订单的订单行级承诺评估：

1. MRP 运算完成；
2. 计划采购订单释放；
3. 计划生产工单释放；
4. 销售端手工点击“重新评估”。

评估快照重新读取库存、采购在途和生产在制，并更新 `erp_sales_order_promise_assessment`。重算失败不回滚已经成功生成的 MRP 结果，但在 MRP 运行记录中保留错误信息。

## 3. 页面与接口

计划页面 `/mes/planning` 展示 MPS、MRP 净需求、未覆盖缺口和计划订单，支持固定、下达和查看最近一次 ATP/CTP 重算数量。

接口：

- `POST /api/v1/mes/planning/mrp-runs`：运行 MRP，完成后自动重算承诺；
- `POST /api/v1/mes/planning/planned-orders/{id}/release`：释放建议并自动重算承诺；
- `POST /api/v1/mes/planning/promise-recalculate`：手工重算所有确认中/部分发货销售订单；
- `GET /api/v1/erp/sales/promise/dashboard`：查看缺料、产能风险和可承诺汇总。

## 4. 验收标准

- 有库存、采购在途或生产在制时，MRP 能按优先级扣减并生成正确净需求。
- 可采购/可生产物料分别生成采购/生产建议；无来源时显示未覆盖缺口。
- 采购或生产建议释放后，销售订单承诺快照的 `assessed_at`、供给数量和风险状态发生更新。
- MRP 运行记录可看到自动重算时间和订单行数量。
- MySQL 迁移可升级、回滚；后端测试、前端类型检查和生产构建通过。
