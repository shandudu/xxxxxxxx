# MES + ERP 设备运维与停机管理模块 PRD V1.0

## 1. 模块目标

设备运维第一期把设备基础资料、现场点检、预防保养、故障维修和 APS 有限产能排程连接起来，形成“计划—任务—执行—停机—恢复”的闭环。系统需要回答：

1. 哪台设备何时需要点检或保养、由谁负责；
2. 运维任务是否按时执行、结果是否合格；
3. 故障从报修到修复经历了哪些状态、成本是多少；
4. 哪些停机区间会占用工作中心产能并影响排程。

## 2. 本期范围

### 2.1 周期运维计划

- 支持点检计划和预防性保养计划；
- 支持按天、周、月滚动周期；
- 支持提前天数、预计工时、负责人和检查清单；
- 可配置执行时是否必须停机；
- 支持启用、停用和修改下一到期日；
- 月度周期采用月末保护，例如 1 月 31 日的下次日期为 2 月最后一天。

### 2.2 运维任务

- 根据指定生成基准日期和各计划的提前天数批量生成可执行任务；
- 同一计划、同一到期日只生成一条有效任务；
- 任务保留生成时的设备、工作中心、负责人、预计工时和检查清单快照；
- 支持待执行、执行中、已完成状态；
- 支持合格、不合格和不适用三类结果；
- 记录检查结果、发现问题和处理措施；
- 需要停机的任务开始时自动建立计划停机，完成时自动关闭；
- 不合格任务可自动生成维修工单。

### 2.3 故障维修

- 支持故障报修、指派、开始维修、完成和取消；
- 记录故障等级、故障描述、根因、维修措施、备件使用说明和维修费用；
- 影响产能的报修自动建立非计划停机并将设备置为停机状态；
- 开始维修后设备进入维护状态；
- 完成或取消维修时关闭对应停机记录；
- 当设备不存在其他未关闭停机时，自动恢复为空闲状态。

### 2.4 停机管理

- 支持人工登记计划停机和非计划停机；
- 支持记录来源、来源业务 ID、原因和是否影响产能；
- 支持开放区间与已结束区间；
- 关闭停机时自动计算停机分钟；
- 关闭时间必须晚于开始时间；
- 同一设备仍有其他开放停机时不恢复设备状态。

### 2.5 运维看板

- 有效计划数；
- 待执行、逾期和执行中任务数；
- 未关闭维修数及重大故障数；
- 未关闭停机数；
- 最近 30 天停机分钟；
- 最近 30 天任务完成率。

## 3. 数据模型

| 表 | 用途 | 主要物理外键 |
| --- | --- | --- |
| `mes_maintenance_plan` | 周期点检/保养计划 | 设备、工作中心、负责人 |
| `mes_maintenance_task` | 到期运维任务及执行结果 | 计划、设备、工作中心、负责人、停机记录 |
| `mes_repair_order` | 故障维修工单 | 设备、工作中心、负责人、停机记录 |
| `mes_equipment_downtime` | 设备停机时间区间 | 设备、工作中心 |

本期共建立 14 条命名物理外键。数据库升级只执行 Alembic 增量迁移，不运行 `fba init`。

## 4. 核心流程

### 4.1 点检/保养闭环

```text
配置周期计划 → 生成到期任务 → 开始任务
                         ├─ 无需停机：直接执行
                         └─ 需要停机：创建计划停机并扣减 APS 产能
                              ↓
                    录入清单和执行结果
                         ├─ 合格：关闭停机并恢复设备
                         └─ 不合格：关闭计划停机并自动生成维修/非计划停机
```

### 4.2 故障维修闭环

```text
故障报修 → 自动建立非计划停机 → 指派维修人 → 开始维修
                                              ↓
                               录入根因、措施、备件和费用
                                              ↓
                                  完成维修并关闭停机
                                              ↓
                              无其他开放停机则恢复设备空闲
```

## 5. APS 产能联动

- APS 加载计划时间窗内所有 `affects_capacity = true` 的停机；
- 已关闭停机使用实际结束时间；
- 未关闭停机从开始时间持续阻断至排程时间窗结束；
- 只有绑定工作中心的停机参与工作中心产能扣减；
- 停机区间会切分班次可用区间，前向、后向排程和负荷分析使用同一组切分结果；
- 不影响产能的记录仅用于设备履历，不改变排程结果。

## 6. 状态规则

| 对象 | 状态流转 |
| --- | --- |
| 运维计划 | `ACTIVE ↔ DISABLED` |
| 运维任务 | `PENDING → IN_PROGRESS → COMPLETED` |
| 维修工单 | `REPORTED → ASSIGNED → IN_REPAIR → COMPLETED` |
| 维修取消 | `REPORTED/ASSIGNED/IN_REPAIR → CANCELLED` |
| 停机记录 | `OPEN → CLOSED` |

状态变更在事务内锁定业务记录，重复开始、重复完成和完成时间早于开始时间均被拒绝。

## 7. 权限

| 权限码 | 说明 |
| --- | --- |
| `mes:maintenance:view` | 查看设备运维工作台 |
| `mes:maintenance:config` | 新建和修改运维计划 |
| `mes:maintenance:generate` | 生成到期运维任务 |
| `mes:maintenance:execute` | 开始和完成点检/保养任务 |
| `mes:maintenance:repair` | 报修、指派、维修、完成和取消 |
| `mes:maintenance:downtime` | 登记和关闭人工停机 |

## 8. 接口范围

- 看板：`GET /api/v1/mes/maintenance/dashboard`；
- 计划：查询、新建、修改、生成到期任务；
- 任务：查询、开始、完成；
- 维修：查询、报修、指派、开始、完成、取消；
- 停机：查询、新建、关闭。

第一期共 17 个 API 路由。

## 9. 一致性与审计规则

- 设备必须启用且允许维护；
- 工作中心必须存在且处于启用状态；
- 负责人必须为有效系统用户；
- 单号按“单号 + 逻辑删除标记”保持唯一；
- 计划生成、任务执行、停机创建/关闭和设备状态修改均在同一数据库事务内；
- 所有业务记录保留创建人、更新人、创建时间、更新时间和逻辑删除字段；
- 自动生成的维修和停机记录保留来源类型及来源业务 ID。

## 10. 本期明确限制

- 暂不支持按设备运行小时、产量或仪表读数触发保养；
- 暂不做备件库存自动领用和采购补货，只记录备件使用说明；
- 暂不做维修人员技能、证书、工时负荷和移动端离线派单；
- 暂不接入 PLC、IoT 告警和预测性维护模型；
- 暂不提供设备树、部件层级和详细维修知识库；
- 一条停机只绑定一个工作中心，设备与多个工作中心的复杂共享关系后续扩展；
- 第一期开工前已发布排程不会被自动重排，停机只影响后续运行的排程版本。
